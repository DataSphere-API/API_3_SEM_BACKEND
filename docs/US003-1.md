# US003-1 — Gerar QR Code por procedimento

> Histórico da US003-1: a US003-5 substitui o contrato HTTP de consulta pelo retorno exclusivo de `codigo`, com validação do dono e sessões completas. Nesta branch, consulte o [guia atualizado da US003-5](US003-5.md). Os services internos e seus testes de regressão continuam disponíveis.

Branch: `feature/US003-1-gerar-qrcode-por-procedimento`, criada a partir de `dev`.

## Endpoint e contrato

```http
GET /atendimentos/{id}/qrcode
```

O ID identifica `Guia_Proc`, não a guia inteira. Resposta 200:

```json
{
  "atendimentoId": 10,
  "codigo": "7f3c9e2a-e94b-4a50-a0f7-b5bf9402ad18",
  "imagemBase64": "data:image/png;base64,iVBOR..."
}
```

O controller devolve `dto.request.QrCodeResponse`. O código é gravado em `Guia_Proc.QR`; a imagem PNG de 300 × 300 pixels é gerada em memória com ZXing, contendo exatamente esse código. A imagem não precisa ser armazenada no banco. As dependências `core` e `javase` usam a mesma versão 3.5.4. Referência: [MatrixToImageWriter, documentação do ZXing](https://zxing.github.io/zxing/apidocs/com/google/zxing/client/j2se/MatrixToImageWriter.html).

Cada procedimento possui seu QR. Se o código já existe, é reaproveitado, inclusive códigos antigos do seed que não são UUID. Para códigos novos, é utilizado `UUID.randomUUID()`. A consulta usa bloqueio pessimista dentro da transação para que chamadas simultâneas ao mesmo atendimento retornem o mesmo código. A migration V15 cria um índice único que impede um mesmo código em dois atendimentos.

## Regras e erros

A guia deve estar `EMITIDA` ou `PARCIALMENTE_REALIZADA`. O enum `StatusGuia` passa a incluir o segundo status. Esta task aceita esse estado; não altera o fluxo existente que calcula o status da guia.

A validade é calculada a partir da data de emissão usando `ValidadeGuiaService` (60 dias por padrão), incluindo o último dia. Uma validade menor já registrada no procedimento também é respeitada. Uma data de validade maior não estende a validade da guia. Sem data de emissão ou com emissão futura, o QR é bloqueado.

As regras são verificadas mesmo se já existir QR: um atendimento expirado ou realizado não volta a ficar disponível apenas por possuir código salvo.

| Situação | Status HTTP / código |
| --- | --- |
| Atendimento inexistente | 404 `ATENDIMENTO_NAO_ENCONTRADO` |
| Guia vencida, guia com status EXPIRADA ou procedimento expirado | 422 `GUIA_EXPIRADA` |
| Procedimento REALIZADA ou FATURADA | 422 `PROCEDIMENTO_JA_REALIZADO` |
| Guia ausente ou fora dos dois status permitidos | 422 `GUIA_NAO_EMITIDA` (erro já existente no projeto) |
| Status desconhecido do procedimento | 400 `STATUS_INVALIDO` |

O enum de procedimento existente usa `EXPIRADA`. A validação também reconhece `EXPIRADO`, conforme o texto do card, e `REALIZADO`, formato legado já tratado pela conferência de QR.

## Services e integração com US005-5

Os serviços ficam em `atendimento.service`, com uma ação por classe:

- `GerarCodigoUnicoQrService.gerarCodigoUnicoQr()`
- `GerarImagemQrCodeService.gerarImagemQrCode(String codigo)`
- `SalvarQrNoProcedimentoService.salvarQrNoProcedimento(GuiaProcModel procedimento, String codigo)`
- `ValidarProcedimentoNaoRealizadoService.validarProcedimentoNaoRealizado(GuiaProcModel procedimento)`
- `GarantirQrDoProcedimentoService.garantirQrDoProcedimento(Long atendimentoId)`

Para a US005-5, injete `GarantirQrDoProcedimentoService` e chame o método público que retorna `String`. Ele valida, busca com bloqueio e persiste ou reaproveita o código. Não gera imagem. A gravação auxiliar exige uma transação existente e deve ser chamada pelo fluxo de garantia do QR.

## Testar no IntelliJ ou Postman

Use JDK 21 ou superior e o perfil `dev`, em um banco de desenvolvimento compatível com esta branch. Não é necessário o perfil `cadastros-mock` da US000-17.

O banco usado na task anterior já pode conter migrations V13/V14 que ainda não estão na `dev`. Nesse caso, use um banco separado para esta task; não apague o banco anterior nem ignore validações do Flyway. A V15 foi escolhida para não ocupar os números V13/V14 usados na branch anterior. A numeração deve ser conferida antes do merge das tasks.

Para testar em um banco separado pela linha de comando, suba um PostgreSQL exclusivo e configure a URL correspondente. Exemplo local sem volume:

```bash
docker run --detach --rm --name fusex-us0031-dev-db \
  -e POSTGRES_DB=fusex_us0031_dev \
  -e POSTGRES_USER=fusex_test \
  -e POSTGRES_PASSWORD=fusex_test_local \
  -p 127.0.0.1:55431:5432 postgres:16-alpine

SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:55431/fusex_us0031_dev \
SPRING_DATASOURCE_USERNAME=fusex_test \
SPRING_DATASOURCE_PASSWORD=fusex_test_local \
SPRING_DOCKER_COMPOSE_ENABLED=false \
./mvnw spring-boot:run -Dspring-boot.run.profiles=dev
```

No IntelliJ, as mesmas quatro variáveis podem ser informadas em **Environment variables** da configuração de execução; em **Active profiles**, use `dev`. Essas credenciais são apenas de exemplo local.

Execute [`requests/us0031.http`](../requests/us0031.http) ou use no Postman:

```http
GET http://localhost:8080/atendimentos/1/qrcode
```

Não há body. Esta task não adiciona autenticação ou headers simulados. O seed dev já possui QR nos atendimentos 1 e 2: repetir a chamada deve preservar seus códigos. Para testar um novo UUID, execute opcionalmente [`requests/us0031-fixture.sql`](../requests/us0031-fixture.sql) nesse banco de desenvolvimento e consulte o atendimento criado. O script cria somente registros novos e devolve seu ID.

## Testes automatizados

```bash
# Testes unitários, controller e decodificação real do PNG
./mvnw clean test

# Inclui integração em PostgreSQL exclusivo de testes
# Usuário/senha esperados: fusex_test / fusex_test_local
US0031_TEST_DB_URL=jdbc:postgresql://localhost:55431/fusex_us0031_test ./mvnw clean test
```

Os testes de integração aplicam as migrations, confirmam o código persistido, a segunda chamada, códigos distintos na mesma guia, erros de negócio e exclusividade no banco. Duas threads também chamam o service em transações separadas e confirmam que o mesmo UUID foi gravado. Sem `US0031_TEST_DB_URL`, a classe de integração é ignorada.
