## Numeração anual

A migration `V18__numero_anual_da_guia.sql`:

- Adiciona `Guia.numero`, obrigatório e único.
- Preenche guias existentes por ano de emissão, ordenando por data de emissão e ID.
- Inicializa `guia_numeracao_anual` com o último número de cada ano.
- Cria um trigger de inserção que atribui os números das novas guias, inclusive na emissão de pré-guia.

Formato: `2026-000123`. A parte sequencial começa em 1 para cada ano, com pelo menos seis dígitos. Valores acima de 999999 não são truncados. O ano vem de `Guia.dataEmissao`, não do ID nem do relógio do banco.

O contador usa `INSERT ... ON CONFLICT ... DO UPDATE ... RETURNING`. O PostgreSQL bloqueia a linha do ano e serializa a atribuição dentro da transação, evitando duplicidade em emissões simultâneas. Uma transação revertida não consome o contador. A constraint única também protege os números gravados.

`GuiaModel.numero` é um campo gerado na inserção, com `@Generated`, somente de leitura para a aplicação. Assim, `CriarGuiaDaPreGuiaService` recebe o número no retorno do `save`, sem outra etapa de gravação ou um cálculo inseguro por `MAX + 1`. Não é necessário fornecer `numero` nos requests.

## Endpoint

```http
GET /beneficiarios/{precCp}/guias
```

A resposta continua sendo uma lista, com os campos anteriores e o novo `numero` em cada guia:

```json
[
  {
    "guiaId": 123,
    "numero": "2026-000123",
    "status": "EMITIDA",
    "dataEmissao": "2026-11-13",
    "diasRestantes": 60,
    "procedimentos": []
  }
]
```

`GuiaBeneficiarioResponse` permanece em `guia.dto.request`. O controller recebe `Principal` e o service verifica autorização **antes** de procurar o beneficiário ou suas guias.

| Identidade/perfil | Resultado |
| --- | --- |
| Beneficiário consultando o próprio Prec-CP | 200 |
| Chefe ou emissor consultando outro beneficiário | 200 |
| Outro beneficiário, sem esses perfis | 403 |
| Médico sem perfil de chefe/emissor consultando terceiro | 403 |
| Sem identidade autenticada | 401 |
| Chefe/emissor consultando beneficiário inexistente | 404 |
| Dono ou perfil permitido, mas sem guias | 200 com lista vazia |

O header `X-Prec-Cp` não autentica nem concede acesso. A consulta de QR da US003-5 mantém sua própria regra: chefe e emissor **não** passam a receber o QR de terceiros por causa desta task.

## Testes locais no Postman/IntelliJ

Use um banco separado, compatível com esta cadeia de branches. Não apague, repare nem ignore migrations dos bancos anteriores. Para os mocks, ative os três perfis **`dev,qrconsulta-mock,guias-mock`**. O perfil normal exige autenticação real e não aceita `X-Mock-Login`.

A V17 da US003-5 fornece os beneficiários, e a V19 adiciona os logins de teste de chefe, emissor e médico, associados aos perfis já existentes no seed:

| X-Mock-Login | Papel |
| --- | --- |
| `00000000351` | Dono do Prec-CP `123456789-00` |
| `00000000352` | Outro beneficiário, Prec-CP `111111111-00` |
| `00000000353` | Chefe |
| `00000000354` | Emissor |
| `00000000355` | Médico sem os perfis acima |

Execute [`requests/us0036.http`](../requests/us0036.http). Para um ambiente isolado pela linha de comando:

```bash
docker run --detach --rm --name fusex-us0036-dev-db \
  -e POSTGRES_DB=fusex_us0036_dev \
  -e POSTGRES_USER=fusex_test \
  -e POSTGRES_PASSWORD=fusex_test_local \
  -p 127.0.0.1:55436:5432 postgres:16-alpine

SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:55436/fusex_us0036_dev \
SPRING_DATASOURCE_USERNAME=fusex_test \
SPRING_DATASOURCE_PASSWORD=fusex_test_local \
SPRING_DOCKER_COMPOSE_ENABLED=false \
./mvnw spring-boot:run -Dspring-boot.run.profiles=dev,qrconsulta-mock,guias-mock
```

No IntelliJ, coloque as quatro variáveis em **Environment variables** e os três perfis em **Active profiles**. Isso não exige alterar o `.env`. As credenciais acima são apenas de exemplo local. Execute a API em um único lugar para não disputar a porta 8080.

## Testes automatizados

```bash
./mvnw clean test

# PostgreSQL exclusivo de testes; credenciais fusex_test / fusex_test_local.
US0036_TEST_DB_URL=jdbc:postgresql://localhost:55436/fusex_us0036_test ./mvnw clean test
```

Os testes verificam a autorização, o campo `numero`, a emissão real da pré-guia com QR, a sequência por ano, a passagem de seis dígitos e quatro emissões concorrentes. Um schema isolado é migrado até V17 e depois V18 para confirmar o backfill de guias antigas e a continuação correta da sequência.

As variáveis `US0035_TEST_DB_URL` e `US0031_TEST_DB_URL` podem habilitar as regressões anteriores, cada uma apontando para outro banco de teste, sem misturar seus seeds.
